fp32 frontend latency: reference vs Triton vs CUDA C
====================================================
RTX 4090. All three run the same fp32 FFT, so the difference is the post-FFT
implementation. Speedups are reference / backend. The Triton batch1/1s 0.19x is
a first-cell autotune warmup artifact, not signal.

Reproduce: PYTHONPATH=src python bench/compare_backends.py

Correctness: the CUDA C kernel matches the fp32 reference exactly (max relative
error 1.2e-07).

Reading: the naive CUDA C kernel wins on tiny inputs (batch 1 to 8, 1 s), where
the frontend is launch-overhead bound and its single fused launch beats the
reference's many kernels. It loses by about 2x on large inputs, where the matmul
dominates and the lack of tensor cores hurts. Nsight (nsight.txt) shows the
per-kernel reason: 114 us for the naive kernel against roughly 20 us for cuBLAS
and the Triton tensor-core kernel.
