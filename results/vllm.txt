Whisper served through vLLM
===========================

Serving the Whisper pipeline (vLLM's own mel frontend, the encoder, and
autoregressive decoding) through the vLLM inference engine, to situate the
frontend work in a serving stack.

Environment: A100 80GB SXM, vLLM 0.11.0, torch 2.8.0+cu128, transformers 4.57.6.
Model: openai/whisper-small. Offline batched throughput over 64 requests of a
15.9 second clip each. vLLM run in eager mode with the spawn worker method,
which Whisper requires on this host.

Result:
  requests      64
  clip length   15.9 s each
  wall time     2.14 s
  throughput    29.9 requests/s
                476 audio-seconds processed per wall-second
  sample        "The first words I spoke in the original phonograph ..."

Reading: vLLM processes about 476 seconds of audio per wall-second here, with
batching and paged attention. The log-mel frontend is a
small fraction of that pipeline, consistent with the 0.3 to 4 percent share
measured directly in whisper_e2e. The frontend fusion in this repo targets that
small slice, so its value is in the frontend microbenchmark and in tail latency
under concurrency, not in raising this engine's throughput.

Deployment note: the latest vLLM targets CUDA 13, which needs driver 580 or
newer. The RTX 4090 and A100 pods used here run driver 570 (CUDA 12.8), so vLLM
0.11.0 built against CUDA 12.8 was used. Installing the newest vLLM first and
downgrading corrupts the cuDNN libraries (CUDNN_STATUS_NOT_INITIALIZED); a clean
install of the CUDA 12.8 build avoids that.
